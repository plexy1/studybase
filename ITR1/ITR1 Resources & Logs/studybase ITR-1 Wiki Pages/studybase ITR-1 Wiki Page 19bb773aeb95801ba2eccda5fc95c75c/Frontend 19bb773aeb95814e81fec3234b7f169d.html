2. index.css

This file, index.css, is a stylesheet that defines the styles for a sign-in form page and some additional UI components. Here's a breakdown of what it does:

1. General Page Styling

  • Ensures html and body take up the full height of the viewport.

2. Sign-in Form Styling (.form-signin)

  • Sets a max width (330px) and padding for a centered form.
  • Styles input fields (email and password) to have appropriate border-radius and spacing.
  • Ensures .form-floating elements maintain their stacking order when focused.

  • Sets font size and disables text selection.
  • A larger font size is applied for screens wider than 768px.

4. UI Elements

  • Dividers (.b-example-divider)
    • A thin horizontal separator with a slight shadow effect.
  • Vertical Rule (.b-example-vr)
    • A vertical divider taking full viewport height.
  • Icons (.bi)
    • Ensures Bootstrap icons align properly.
  • Navigation Scroller (.nav-scroller)
    • Makes the navigation bar horizontally scrollable.

5. Custom Button Styling (.btn-bd-primary)

  • Defines a primary button style with a violet background.
  • Uses CSS variables to control hover, active, and focus states.
  • Text color remains white across all states.

  • Ensures the mode toggle has a high z-index (1500) so it stays above other elements.
  • Displays the correct icon when active.

7. Error Messages (.messageDiv)

  • Defines an error message container, which is hidden by default and appears in red.

8. Status Button (.status-button)

  • A floating button positioned at the top-right for checking system status.
  • Changes color when hovered.
  • Displays additional info (Operational, click for detailed status) when hovered.

Conclusion

This index.css file is primarily used for a sign-in page, featuring form styling, navigation adjustments, UI elements, error messages, and a system status button.

Vertical Divider (.b-example-vr)

  • Defines a vertical line (1.5rem wide) with a height of 100% of the viewport.

Icons (.bi)

  • Ensures Bootstrap icons align properly with other elements by adjusting the vertical alignment and fill color.

Navigation Scroller (.nav-scroller)

  • Styles the navigation bar to make it scrollable horizontally with overflow-x: auto and no vertical overflow.
  • Adds custom padding and adjusts the appearance of the navigation.

Primary Button Styling (.btn-bd-primary)

  • Uses CSS variables for defining the violet button appearance:
    • Default background color is violet (#712cf9).
    • Hover and active states have different background colors.
    • Font weight, text color, and border colors are also controlled by variables.

Dark Mode Toggle (.bd-mode-toggle)

  • Ensures the dark mode toggle has a high z-index (1500) so it stays visible over other elements.
  • Active state styles the toggle icon.

Error Messages (.messageDiv)

  • Defines an element for error messages, which is hidden by default and shown when needed.
  • Red text color is used to indicate errors.

Duplicate/Redundant Rules

Some of the styles, particularly for btn-bd-primary, bd-placeholder-img, and .bd-mode-toggle, are repeated within the file. This redundancy should ideally be removed to keep the stylesheet clean and efficient. Specifically, the definitions of .btn-bd-primary, .bd-placeholder-img, and .bd-mode-toggle are duplicated multiple times, but they contain the same properties each time.

Conclusion

This file is intended to style a sign-in page, with a primary focus on form styling, UI elements (e.g., buttons, dividers), navigation adjustments, and error handling. There are also duplicate styles that could be consolidated to improve readability and performance.

5. search-topic.html

The search-topic.html file is a key component of the application, designed to allow users to search for topics, courses, and quizzes while also viewing their search history. The layout is structured using Bootstrap 5 for responsiveness and styling.

Key Features:

  1. Navbar:
    • Contains links to other sections of the platform, including:
      • Search Topic
      • Search Course
      • Generate Quiz
      • History
      • Account & Settings
    • The logo and profile image are displayed, with a profile picture shown on the right side of the navbar.
  1. Search Functionality:
    • A search box allows users to input any topic or concept to search.
    • Once the search button is clicked, the input value is processed to trigger search results from both Google and YouTube.
    • The search history is stored in cookies, allowing users to view past searches. The history is updated and displayed dynamically on the page.
  1. Results Display:
    • The search results are divided into two sections:
      • Left Half: Displays Google search results.
      • Right Half: Displays YouTube video search results.
    • Both sections have "Previous" and "Next" buttons to navigate through the results, though these are initially hidden.
  1. Cookie Management:
    • The file utilizes cookies to save and display search history across sessions. The history is stored as a JSON object and persists for 30 days.
    • A function getCookie() is used to retrieve the stored history, and setCookie() is used to update the cookie.
  1. JavaScript:
    • The script handles:
      • Retrieving search input when the search button is clicked.
      • Managing search results and interacting with Google and YouTube APIs.
      • Storing and displaying search history via cookies.
      • Dynamically updating the history display on the page.
    • Event listeners are attached to elements such as the search button and back-to-login button for proper navigation and functionality.
  1. Footer:
    • Contains links to social media accounts (Instagram, Twitter, LinkedIn).
    • The footer has a dark theme with light text, consistent with the overall styling of the page.
  1. External Scripts:
    • Bootstrap JS for managing Bootstrap components.
    • External JavaScript files (google-search.js and youtube-search.js) for handling the logic of fetching search results from Google and YouTube respectively.

File Breakdown:

  • HTML Structure:
    • Main structure with Bootstrap classes to ensure the page is responsive.
    • A <nav> element for navigation, a <div> for the search box, and sections to display results.
  • CSS:
    • The page uses an external search-topic.css file for custom styling.
    • It ensures proper layout, padding, margins, and button styling.

Summary:

This file serves as a central part of the search experience within the web application. It integrates multiple APIs (Google and YouTube) to provide users with topic-related search results while maintaining a clean, user-friendly interface with options for past search history and navigation.

This CSS code styles the Service Status Page and leverages colors to visually indicate the status of the various services. The color scheme is carefully chosen to provide clear and intuitive visual cues about the operational state of each service.

Color Usage for Status Reporting:

  1. Operational Status:
    • Green is used to indicate that a service is operational.
      • .status.ok: The background color is set to a light green (#d4edda), with dark green text (#0f5132) to ensure good contrast and readability. This color choice represents success and indicates that everything is working as expected.
      • The border is also light green (#badbcc), reinforcing the positive status.
  1. Issue/Outage Status:
    • Red is used to indicate that a service has an issue or is experiencing an outage.
      • .status.error: The background color is set to a light red (#f8d7da), with dark red text (#842029) to indicate a problem. This color choice represents error or failure, signaling that something is wrong.
      • The border is a darker red (#f5c2c7), providing a subtle but noticeable contrast to the background.
  1. Service Boxes:
    • The service boxes themselves are styled with a white background, giving them a clean and neutral look. These boxes use box shadows and rounded corners to make the content stand out visually.
  1. Buttons and Hover Effects:
    • The "Report an Issue" button (#report-btn) is styled with a light gray background and changes to a dark red on hover (rgb(200, 35, 51)), creating a sense of urgency when the user wants to report an issue. This color change draws attention to the button when interacting with it.

Summary:

  • Green indicates that services are working well and operational.
  • Red highlights any issues or outages, signaling a need for attention.
  • These color choices help users quickly assess the health of services, improving user experience and accessibility.
